    What I found in your data

    • The Monitor answers for dates it has no data for. Asked for a date without a file, the Monitor API returns the latest day's findings. Only the 86 dates in availableDates are real (Jun 16 to Nov 2, 2026, plus Apr 6, 2026).
    • A person listed as an agent. The Monitor's agentsInvolved field sometimes names a person. Counted as an agent, one person became a recurring agent-and-flag pair on 21 days.
    • Who gets credited with a false claim. A finding often names the agent that made a claim and the agent that caught it. Counting it for every agent named put Claude Opus 5 at 72%; crediting each finding to its subject puts it at 5%.
    • Allowed, and flagged again every day. 8 agent-and-flag pairs were raised on 20 or more days where the Monitor's own notes say the action was allowed.

    How I used AI

    Claude Code wrote most of the code and did the counting. These are the times its first answer was wrong, and how each was caught.

    Data: AI Digest, AI Village dataset, 2026. Used for research under its terms.

    • A median of 56 minutes to an outreach decision came from matching on a missing field. Recomputed by request id
    • The dataset's schema doc said about 25 outreach requests; counting the events showed hundreds (452 in this export)
    • A chain of emails was in file order, which put a decline after the claims. Re-sorted by timestamp
    • A name scrubber over-tagged, putting "[person]" on chapter titles. Held for a manual read
    • A keyword count read speed claims ("tested at 0.12s") as endorsements
    • 56 of 140 days pulled from the Monitor were copies of another day. Caught by comparing each file's date and finding ids
    • The first name scrubber passed its own check but missed about 130 identifiers. Caught by reading the output, not the regex
    • The latest-day problem came back in a new form and counted 141 Monitor days instead of 86
    • October looked like the busiest month ever; more than half of it was scaffold bookkeeping, not work
    • "Idling is a trait of the model" was wrong: the same agent swings 40 to 70 points by month
    • The scrubber replaced agent @-mentions with person stand-ins. Fixed by protecting agent names
    • A person in the Monitor's agent list was counted as an agent. Caught by the privacy check
    • A privacy check passed while real names sat in newly added rows, because it only knew names already on its list. Caught by a full read before publishing
